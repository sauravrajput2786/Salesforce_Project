# Plan 05-01: CSAT Survey Trigger, Immutability Refinement & Sync Service

## Objective

Implement the automated Customer CSAT Survey trigger engine upon Case closure with strict idempotency protection ([CSAT-01](file:///home/elsner/Salesforce/SalesforceProject/.planning/REQUIREMENTS.md)), refine the data immutability validation rule to permit initial customer response ingestion while locking against subsequent agent tampering, and deploy the `CSATSurveyService` Apex engine ([CSAT-02](file:///home/elsner/Salesforce/SalesforceProject/.planning/REQUIREMENTS.md)).

## Context

- `05-CONTEXT.md` Decision D-01: Record-Triggered Flow `Case_CSAT_Survey_Trigger` firing on Case closure with strict idempotency guard `CSAT_Sent__c == false` to prevent duplicate emails upon case reopen and re-closure.
- `05-CONTEXT.md` Decision D-02: Professional HTML email template `Case_CSAT_Survey_Invitation` with Case merge fields.
- `05-CONTEXT.md` Decision D-03: Hybrid immutability rule in `VR_Case_Lock_Customer_And_SLA_Data` allowing initial population of `Customer_Rating__c` and `Feedback_Comments__c` when previously blank, while locking against modifications thereafter.
- `05-CONTEXT.md` Decision D-04: `CSATSurveyService.cls` for validated bulk survey response recording.

<threat_model>
### Threat Modeling & Risk Register

| Threat ID | Category | Description | Severity | Mitigation Strategy |
|-----------|----------|-------------|----------|---------------------|
| T-05-01 | Operational / Spam | Reopening and re-closing a ticket repeatedly dispatches duplicate CSAT survey emails to the customer. | High | Check `CSAT_Sent__c == false` in Flow entry criteria and stamp `CSAT_Sent__c = true` upon first dispatch. |
| T-05-02 | Data Tampering / Governance | Support agents alter unfavorable customer CSAT ratings (e.g. 1 Star -> 5 Stars) to artificially inflate performance metrics. | Critical | Refine `VR_Case_Lock_Customer_And_SLA_Data` with `NOT(ISBLANK(TEXT(PRIORVALUE(Customer_Rating__c))))`, making existing ratings strictly immutable. |
| T-05-03 | Data Integration Failure | Automated survey submission fails because the validation rule locks all edits to closed cases. | High | Permit initial write when prior value is blank; allow `Bypass_Case_Lock` permission for administrative override. |
| T-05-04 | Governor Limits / Bulk Safety | High-volume batch closures hit SOQL/DML limits during email dispatch or response sync. | Medium | Implement bulk collection processing and single DML in `CSATSurveyService.cls`. |
</threat_model>
