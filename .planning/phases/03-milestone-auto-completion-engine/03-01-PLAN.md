# Plan 03-01: Milestone Auto-Completion Apex Service & Triggers (Fix BUG-001)

## Objective

Implement an enterprise Apex Service and Trigger architecture ([MilestoneCompletionService.cls](file:///home/elsner/Salesforce/SalesforceProject/force-app/main/default/classes/MilestoneCompletionService.cls), [EmailMessageTrigger.trigger](file:///home/elsner/Salesforce/SalesforceProject/force-app/main/default/triggers/EmailMessageTrigger.trigger), [CaseTrigger.trigger](file:///home/elsner/Salesforce/SalesforceProject/force-app/main/default/triggers/CaseTrigger.trigger)) that automatically completes open Service Cloud milestones (`CompletionDate = System.now()`) on outbound customer communications (`EmailMessage` with `Incoming == false`) and Case closure (`Status = 'Closed'`), resolving **BUG-001** and ensuring zero orphaned milestone timers.

## Context

- `03-CONTEXT.md` Decision D-01: Apex service pattern (`MilestoneCompletionService.cls`) driven by `EmailMessageTrigger` and `CaseTrigger` for 100% bulk safety and direct junction query optimization.
- `03-CONTEXT.md` Decision D-02: Complete "First Response to Customer" milestone strictly on outbound customer emails (`Incoming == false` and `ParentId` is Case).
- `03-CONTEXT.md` Decision D-03: Complete ALL remaining open milestones (`CompletionDate == null`) when Case transitions to `Status = 'Closed'`.
- `03-CONTEXT.md` Decision D-04: Comprehensive idempotency guard: filter `CompletionDate == null`, verify status change (`oldCase.Status != 'Closed' && newCase.Status == 'Closed'`), skip non-entitled cases (`EntitlementId == null`), and use static recursion set `processedCaseIds`.

| Threat ID | Category | Description | Severity | Mitigation Strategy |
|-----------|----------|-------------|----------|---------------------|
| T-03-01 | Operational / Data Integrity | Repeated outbound emails or repeat Case updates trigger duplicate milestone queries and redundant DML. | Medium | Filter SOQL query strictly by `CompletionDate = null` and check static `Set<Id> processedCaseIds`; skip DML if list is empty. |
| T-03-02 | Availability / Lock Contention | Concurrently updating CaseMilestones during high-volume email ingestion blocks email sends. | Medium | Wrap milestone updates in defensive try-catch with debug logging and bulk collection processing. |
| T-03-03 | Data Governance | Unentitled cases or non-case EmailMessages trigger unnecessary queries. | Low | Verify `ParentId` begins with `500` (Case prefix) and check `EntitlementId != null` prior to querying `CaseMilestone`. |
| T-03-04 | Governor Limits / CPU | Bulk email intake triggers SOQL or DML limits inside loops. | High | Query and update all milestones in bulk outside loops using single SOQL query and single update DML per transaction. |
</threat_model>

<action>
Create `force-app/main/default/classes/MilestoneCompletionService.cls` and `force-app/main/default/classes/MilestoneCompletionService.cls-meta.xml`:
1. Define `public with sharing class MilestoneCompletionService`:
   - Static recursion guard: `private static Set<Id> processedFirstResponseCases = new Set<Id>();` and `private static Set<Id> processedClosedCases = new Set<Id>();`.
2. Method `public static void completeFirstResponseMilestones(List<EmailMessage> emails)`:
   - Extract unique `CaseId`s from `emails` where `Incoming == false`, `ParentId != null`, `ParentId.getSObjectType() == Case.sObjectType`, and `!processedFirstResponseCases.contains(ParentId)`.
   - If `caseIds.isEmpty()`, return immediately.
   - Mark `processedFirstResponseCases.addAll(caseIds)`.
   - Query: `[SELECT Id, CaseId, CompletionDate FROM CaseMilestone WHERE CaseId IN :caseIds AND MilestoneType.Name = 'First Response to Customer' AND CompletionDate = null]`.
   - If empty, return.
   - For each milestone, set `CompletionDate = System.now()`.
   - Execute bulk `update milestonesToUpdate;`.
3. Method `public static void completeCaseCloseMilestones(List<Case> cases, Map<Id, Case> oldCaseMap)`:
   - Extract `CaseId`s where `c.Status == 'Closed'` and `(oldCaseMap == null || oldCaseMap.get(c.Id).Status != 'Closed')`, `c.EntitlementId != null`, and `!processedClosedCases.contains(c.Id)`.
   - If `closedCaseIds.isEmpty()`, return immediately.
   - Mark `processedClosedCases.addAll(closedCaseIds)`.
   - Query: `[SELECT Id, CaseId, CompletionDate FROM CaseMilestone WHERE CaseId IN :closedCaseIds AND CompletionDate = null]`.
   - If empty, return.
   - For each milestone, set `CompletionDate = System.now()`.
   - Execute bulk `update milestonesToUpdate;`.
4. Method `public static void resetRecursionGuards()` for unit testing reset.
</action>

- Implements `completeCaseCloseMilestones` completing all open milestones where `CompletionDate = null` on Case closure.
- Enforces static recursion sets and null checks with 0 DML when no milestones exist.

## Must-Haves

### Truths
- Sending an outbound email (`Incoming == false`) completes the active "First Response to Customer" milestone.
- Incoming customer emails (`Incoming == true`) do not complete the First Response milestone.
- Closing a Case (`Status = 'Closed'`) completes all active open milestones on the ticket.
- Subsequent emails and repeat edits on closed cases execute cleanly with zero extraneous DML statements.
