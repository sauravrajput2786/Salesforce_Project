# Plan 03-02: Milestone Auto-Completion Engine Unit Testing & BUG-001 Verification

## Objective

Create a comprehensive Apex unit test suite ([MilestoneCompletionServiceTest.cls](file:///home/elsner/Salesforce/SalesforceProject/force-app/main/default/classes/MilestoneCompletionServiceTest.cls)) verifying that outbound customer emails complete the "First Response to Customer" milestone ([MILE-01](file:///home/elsner/Salesforce/SalesforceProject/.planning/REQUIREMENTS.md)), Case closure completes all remaining open milestones ([MILE-02](file:///home/elsner/Salesforce/SalesforceProject/.planning/REQUIREMENTS.md)), incoming emails are ignored, subsequent communications execute idempotently ([MILE-03](file:///home/elsner/Salesforce/SalesforceProject/.planning/REQUIREMENTS.md)), and bulk transactions process safely within governor limits.

## Context

- `03-01-PLAN.md`: `MilestoneCompletionService.cls` handles both outbound email events and Case closure events with static recursion sets and null filters.
- `EmailMessageTrigger.trigger` fires on `after insert` of `EmailMessage`.
- `CaseTrigger.trigger` fires on `after update` of `Case`.
- Unit tests must validate both standalone service invocation and trigger dispatch in single and bulk execution modes.

</threat_model>

### Task 1: Create `MilestoneCompletionServiceTest.cls` Apex Test Class

<read_first>
- `force-app/main/default/classes/MilestoneCompletionService.cls`
- `force-app/main/default/triggers/EmailMessageTrigger.trigger`
- `force-app/main/default/triggers/CaseTrigger.trigger`
- `force-app/main/default/classes/CasePriorityGuardTest.cls`
</read_first>

<action>
Create `force-app/main/default/classes/MilestoneCompletionServiceTest.cls`:
- `@IsTest` annotation and `private class MilestoneCompletionServiceTest`.
- `@TestSetup` method `setupTestData()`:
  - Create test `Account` ("Milestone Test Account").
  - Create test `Contact` ("Customer Contact") linked to Account.
  - Create test `Case` ("Milestone First Response Ticket", `Status = 'New'`, `Priority = 'Medium'`, `Origin = 'Web'`).
  - Create second test `Case` ("Milestone Closure Ticket", `Status = 'New'`, `Priority = 'High'`, `Origin = 'Web'`).
- Test method `testOutboundEmailCompletesFirstResponse()`:
  - Reset recursion guards via `MilestoneCompletionService.resetRecursionGuards()`.
  - Insert outbound `EmailMessage` (`Incoming = false`, `ParentId = caseId`, `ToAddress = 'customer@example.com'`).
  - Verify trigger executes cleanly without errors and service handles the outbound event.
- Test method `testIncomingEmailDoesNotTriggerFirstResponse()`:
  - Reset recursion guards.
  - Insert inbound `EmailMessage` (`Incoming = true`, `ParentId = caseId`, `FromAddress = 'customer@example.com'`).
  - Verify incoming email is cleanly bypassed and no milestones are erroneously updated.
- Test method `testCaseClosureMilestoneCompletion()`:
  - Reset recursion guards.
  - Update Case `Status = 'Closed'`.
  - Verify `CaseTrigger` dispatches to `completeCaseCloseMilestones` and executes cleanly.
- Test method `testIdempotencyAndRepeatExecutions()`:
  - Insert 2 consecutive outbound emails on the same case.
  - Verify second email executes with zero redundant DML or errors.
- Test method `testBulkEmailAndCaseClosure()`:
  - Bulk insert 20 outbound emails across 20 cases.
  - Bulk update 20 cases to `Status = 'Closed'`.
  - Verify no governor limit exceptions occur.
</action>
