# Plan 01-02: Critical Priority Downgrade Protection & Verification

## Objective

Implement a lightweight Before-Save record-triggered flow (`Case_Critical_Priority_Guard`) on `Case` ensuring that any ticket already marked `Critical` (e.g. system outages, high-severity defects) is strictly immune from being downgraded to `High` by automated workflow field updates or milestone violation actions.

## Context

- `01-CONTEXT.md` Decision D-04: When milestone SLA violation triggers `ChangePriorityToHigh`, tickets already marked `Critical` must not be downgraded to `High`.
- Fast Field Update (`RecordBeforeSave`) on `Case` executes in-memory with 0 additional DML statements, ensuring zero governor limit impact.
- Complies with `VR_Case_Lock_Customer_And_SLA_Data` which restricts modifications to customer intake and SLA metrics.

### Task 1: Create `Case_Critical_Priority_Guard` Before-Save Flow

<read_first>
- `force-app/main/default/flows/Case_Entitlement_Gatekeeper.flow-meta.xml`
- `force-app/main/default/objects/Case/fields/Priority.field-meta.xml`
- `.planning/phases/01-sla-entitlement-warning-synchronization/01-CONTEXT.md`
</read_first>

<action>
Create `force-app/main/default/flows/Case_Critical_Priority_Guard.flow-meta.xml`:
- Flow type: `AutoLaunchedFlow`
- Trigger: `RecordBeforeSave` on `Case` (`Update`)
- Condition filter:
  - `ISCHANGED($Record.Priority)`
  - `PRIORVALUE($Record.Priority) == 'Critical'`
  - `$Record.Priority == 'High'`
- Action:
  - Assignment element: `$Record.Priority = 'Critical'`
  - Description: "Enterprise Priority Immunity: Prevents automated SLA breach actions or agent edits from downgrading an existing Critical priority ticket to High."
- Status: `Active`
</action>

<acceptance_criteria>
- File `force-app/main/default/flows/Case_Critical_Priority_Guard.flow-meta.xml` exists.
- Contains `<triggerType>RecordBeforeSave</triggerType>` and `<recordTriggerType>Update</recordTriggerType>`.
- Evaluates `$Record.Priority` change from `Critical` to `High`.
- Reassigns `$Record.Priority` to `Critical`.
- Status is `<status>Active</status>`.
</acceptance_criteria>

## Must-Haves

### Truths
- Cases with `Priority = 'Critical'` cannot be downgraded to `High` by automated SLA violation actions.
- Non-Critical cases can be elevated to `High` on 100% SLA breach without error.
- Zero DML statements executed in before-save flow.
