# Plan 02-02: Single-Admin Escalation Engine Unit Testing & Governance Verification

## Objective

Create an enterprise Apex test suite ([CaseEscalationFlowTest.cls](file:///home/elsner/Salesforce/SalesforceProject/force-app/main/default/classes/CaseEscalationFlowTest.cls)) verifying that Case escalation logic operates cleanly in a single-license Developer Edition environment without manager dependencies (`User.ManagerId`), accurately applies 72h critical telemetry (`Priority = 'Critical'`, `Escalation_Reason__c = 'SLA Breach Risk'`, `IsEscalated = true`), handles both User-owned and Queue-owned tickets, and respects closed-case bypass rules.

## Context

- `02-CONTEXT.md` & `02-01-PLAN.md`: `Case_Escalation_Flow` removes `UserRole` and `User.ManagerId` lookups, queries active System Administrator, posts in-app Chatter notices at 24h, 48h, 72h, and updates 72h telemetry.
- Requirements `ESC-01`, `ESC-02`, `ESC-03`: Single-admin targeting, telemetry stamping, and bulk-safe execution.
- Project testing patterns: `@IsTest`, `@TestSetup`, `System.assertEquals`, adhering to `with sharing`.

### Threat Modeling & Risk Register

| Threat ID | Category | Description | Severity | Mitigation Strategy |
|-----------|----------|-------------|----------|---------------------|
| T-02-05 | Code Quality / Regression | Apex tests depend on org-specific UserRole "Support Manager" causing tests to fail in clean sandboxes or scratch orgs. | High | Test setup verifies single System Administrator execution without asserting or querying `UserRole`. |
| T-02-06 | Security / Mixed DML | Inserting User records and standard Account/Case records in the same test setup causes `System.MixedMmlException`. | Medium | Run User DML inside `System.runAs()` or query existing running System Administrator user. |
| T-02-07 | Execution / Governor Limits | Bulk Case processing triggers CPU or SOQL limits when scheduled paths execute on multiple records. | Medium | Test with multiple Case records verifying bulk safety and collection handling outside loops. |
</threat_model>

<action>
Create `force-app/main/default/classes/CaseEscalationFlowTest.cls`:
- Annotate with `@IsTest` and declare `private class CaseEscalationFlowTest`.
- `@TestSetup` method `setupTestData()`:
  - Create test `Account` ("Escalation Test Account").
  - Create test open `Case` ("Unresolved Ticket 24h", `Status = 'New'`, `Priority = 'Low'`, `Origin = 'Web'`).
  - Create test closed `Case` ("Closed Ticket", `Status = 'Closed'`, `Priority = 'Low'`, `Origin = 'Web'`).
- Test method `testSingleAdminResolution()`:
  - Verify that an active User with `Profile.Name = 'System Administrator'` exists and can be retrieved dynamically without `UserRole`.
- Test method `test72HourCriticalEscalationTelemetry()`:
  - Simulate 72h critical escalation by applying `Priority = 'Critical'`, `Escalation_Reason__c = 'SLA Breach Risk'`, and `IsEscalated = true`.
  - Assert that all three fields are successfully stamped and queryable.
  - Assert that `Case_Critical_Priority_Guard` keeps `Priority` as `'Critical'` even if an external caller attempts to revert it to `'High'`.
- Test method `testClosedCaseEscalationBypass()`:
  - Verify that closed cases (`IsClosed == true`) remain unchanged and do not have escalation flags asserted.
- Test method `testBulkEscalationSafety()`:
  - Insert a batch of 20 test Cases to ensure no governor limit exceptions or DML collision occurs.
</action>
