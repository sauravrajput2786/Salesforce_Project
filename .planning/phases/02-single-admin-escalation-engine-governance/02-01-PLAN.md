# Plan 02-01: Single-Admin Escalation Engine Flow Reconfiguration

## Objective

Reconfigure [Case_Escalation_Flow.flow-meta.xml](file:///home/elsner/Salesforce/SalesforceProject/force-app/main/default/flows/Case_Escalation_Flow.flow-meta.xml) to remove all multi-tier `UserRole` (`Support Manager`) and manager hierarchy (`User.ManagerId`) dependencies, targeting the System Administrator directly for single-license Developer Edition org compatibility. Restructure escalation channels by replacing 24h and 48h email actions with in-app Case Chatter feed posts, reserving email notifications strictly for the 72h Critical Escalation alert, and stamping full telemetry (`Priority = 'Critical'`, `Escalation_Reason__c = 'SLA Breach Risk'`, `IsEscalated = true`).

## Context

- `02-CONTEXT.md` Decision D-01: Query active `User` where `Profile.Name = 'System Administrator'` and `IsActive = true` (sorted by `CreatedDate ASC`, `getFirstRecordOnly = true`), with fallback formula `IF(ISBLANK({!Get_System_Administrator_User.Email}), {!$User.Email}, {!Get_System_Administrator_User.Email})`. Remove obsolete `UserRole` lookups.
- `02-CONTEXT.md` Decision D-02: Post Chatter notice on the Case feed at all three thresholds (24h, 48h, 72h) via `FeedItem` create action for console audit visibility in `Case_Record_Page`.
- `02-CONTEXT.md` Decision D-03: Remove 24h and 48h `emailSimple` actions to prevent admin inbox flooding. Reserve email alerts exclusively for 72h Critical Escalation.
- `02-CONTEXT.md` Decision D-04: If Case is owned by a User (`005`), tag the Case Owner at 24h; if owned by a Queue (`00G`) or unassigned, tag the System Administrator.
- `02-CONTEXT.md` Decision D-05: At 72h, update `Priority = 'Critical'`, `Escalation_Reason__c = 'SLA Breach Risk'`, and `IsEscalated = true`.
- `02-CONTEXT.md` Decision D-06: Maintain bulk-safe execution with entry filter `IsClosed == false` and decision checks on each scheduled path.

### Threat Modeling & Risk Register

| Threat ID | Category | Description | Severity | Mitigation Strategy |
|-----------|----------|-------------|----------|---------------------|
| T-02-01 | Operational / Availability | Flow fails in single-license Dev orgs due to missing `UserRole` "Support Manager" or null manager IDs. | High | Query `User` directly by `Profile.Name = 'System Administrator'` and `IsActive = true`, with fallback formula to `{!$User.Email}`. |
| T-02-02 | Operational / Spam | Support administrators are spammed with high volumes of routine 24h and 48h email notifications. | Medium | Remove 24h/48h email actions; post to Case Chatter feed for console auditability; reserve email alerts strictly for 72h Critical threshold. |
| T-02-03 | Data Integrity | Setting `Priority = 'Critical'` at 72h could be reverted by subsequent SLA violation triggers or agent edits. | High | Rely on `Case_Critical_Priority_Guard` (Phase 1) which prevents any downgrade from Critical to High. |
| T-02-04 | Platform / Limits | Queue-owned cases fail when looking up `User` where `Id = $Record.OwnerId`. | Medium | Check if `Owner:User.Id` is populated; if assigned to a Queue (`00G`), tag System Administrator without throwing null reference exceptions. |
</threat_model>
